# AI Governance Sprint 1 — Audit Model

## Required event fields

| Field | Purpose |
|-------|---------|
| Timestamp | When the event occurred |
| Agent | Responsible agent identity |
| Action | Governed operation |
| Target | Resource or version affected |
| Result | Success, denied, pending, or warning |
| Risk | Low, medium, high, or critical |
| Approval status | Human gate outcome |
| Evidence reference | Resolvable test, decision, diff, commit, or report reference |

## Modeled actions

- Prompt change
- Branch creation
- Worktree creation
- File modification
- Test execution
- Commit approval
- Push
- Merge request
- Deployment request
- Permission change
- Owner override

## Integrity rules

1. Append-only after acceptance.
2. Timestamps generated by trusted server time.
3. Actor identity derived from trusted identity, not request body.
4. Evidence references validated before event finalization.
5. Denied and failed events retained.
6. Retain at least one year; longer for Production, permission, and owner-override events.
7. No credentials, secrets, or raw client payloads in audit details.

## Phase 1

Audit records are synthetic in-memory data. They demonstrate presentation and validation only.
